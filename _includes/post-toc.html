GitHub Pages only runs the gems on its allowlist and this site's `plugins:` list is just jekyll-watch, so jekyll-toc is off the table, so we scrape the headings out of the already rendered post HTML instead. Why scrape the rendered HTML rather than the Markdown source: kramdown's auto_ids is on (it ships on by default and nothing in _config.yml turns it off), so every heading already arrives here carrying the exact `id` the browser needs for the fragment jump. Reading those ids back out means we can never disagree with the anchor we are linking to, including kramdown's own collision handling, where a second "Games" heading becomes id="games-1". If we slugged the heading text ourselves we would have to re-implement that de-duplication and would still drift the moment kramdown changed its rules. Honours the `toc: true` default that _config.yml sets for everything in _posts, so an individual post can opt out with `toc: false` in its front matter.
